# RouterVault

Self-hosted сервис для автоматического создания, шифрования и хранения резервных копий MikroTik RouterOS в любом S3-совместимом хранилище.

RouterVault предоставляет современную веб-панель, проверяет доступ к устройствам, создаёт одновременно бинарный `.backup` и читаемый `.rsc`, показывает ход выполнения и позволяет безопасно скачать результат из S3.

## Основные возможности

- добавление MikroTik по IP-адресу или hostname через SSH/SFTP;
- автоматическая проверка подключения при добавлении и редактировании устройства;
- получение `identity`, версии RouterOS и SSH fingerprint;
- создание зашифрованного `.backup` с индивидуальным AES-паролем;
- создание текстового экспорта `.rsc`;
- загрузка файлов в S3 с понятными именами, содержащими IP, дату и время;
- SHA-256 для проверки целостности каждого файла;
- ручной запуск одного устройства или всей группы;
- ограниченный параллельный запуск без дублирования активных процессов;
- расписание, политика хранения и автоматическая очистка старых запусков;
- история со статусом, размером, этапом, ошибкой и количеством SSH-попыток;
- скачивание `.backup` и `.rsc` через краткоживущие подписанные S3-ссылки;
- сохранение пароля восстановления для каждого `.backup`;
- резервная копия собственной базы RouterVault в S3;
- профиль администратора, смена и восстановление пароля через SMTP;
- мастер первоначальной настройки администратора, SMTP, S3 и расписания;
- тёмный адаптивный интерфейс для компьютеров и мобильных устройств.

## Как работает резервное копирование

1. RouterVault блокирует повторный запуск того же устройства.
2. Устанавливает SSH-соединение и проверяет fingerprint устройства.
3. Создаёт на RouterOS зашифрованный `.backup` и текстовый `.rsc`.
4. Получает оба файла по SFTP во временный каталог контейнера.
5. Вычисляет SHA-256 и загружает объекты в настроенный S3 bucket.
6. Удаляет временные файлы с MikroTik и из контейнера.
7. Сохраняет результат и диагностические данные в локальную SQLite-базу.

Пароли MikroTik, S3 и SMTP хранятся в базе только в зашифрованном виде. Ключом шифрования служит `MASTER_KEY`, переданный контейнеру через окружение.

## Требования

- Docker Engine с поддержкой Docker Compose;
- доступ контейнера к MikroTik по SSH/SFTP;
- RouterOS 6 или 7;
- S3-совместимое хранилище;
- SMTP-сервер для восстановления пароля;
- HTTPS reverse proxy для публичного размещения.

## Быстрый запуск через Docker Compose

```bash
cp .env.example .env
docker compose up -d --build
```

Перед запуском обязательно замените `MASTER_KEY` в `.env` на случайную строку длиной не менее 24 символов. Рекомендуется использовать 32–64 случайных символа.

Откройте `http://адрес-сервера:8080` и пройдите мастер первоначальной настройки. Мастер создаст администратора, проверит SMTP и S3, создаст bucket при необходимости и сохранит расписание.

## Развёртывание в Portainer

В репозитории находится файл `docker-compose.portainer.yml`, рассчитанный на развёртывание из Git и подключение к существующему Nginx Proxy Manager.

1. Создайте Stack из Git repository.
2. Укажите путь `docker-compose.portainer.yml`.
3. Добавьте постоянную переменную `MASTER_KEY`.
4. При необходимости задайте `TZ`, `SESSION_TTL_HOURS` и `BACKUP_WORKERS`.
5. Разверните стек.
6. В Nginx Proxy Manager направьте домен на `routervault:8080`.

По умолчанию используется внешняя сеть `angie_nmp_portainer-web-net`. Если сеть reverse proxy называется иначе, измените `networks.proxy.name`.

Приложение не публикует порт напрямую наружу, запускается без Linux capabilities, с `no-new-privileges`, read-only root filesystem и отдельным volume для `/data`.

## Подготовка MikroTik

Создайте отдельную группу и пользователя. Не используйте основную учётную запись администратора маршрутизатора.

```routeros
/user group add name=routervault policy=ssh,ftp,read,write,policy,test,sensitive
/user add name=routervault group=routervault password="ЗАМЕНИТЕ_НА_СЛОЖНЫЙ_ПАРОЛЬ"
/ip service set ssh disabled=no port=22
```

В firewall разрешите TCP/22 только с IP-адреса сервера RouterVault. Если SSH использует другой порт, укажите одинаковое значение на MikroTik и в веб-панели.

Набор прав зависит от версии RouterOS. Права `policy`, `test` и `sensitive` могут потребоваться для полного `/system backup save`. После настройки обязательно используйте кнопку проверки доступа.

## S3

Поддерживаются MinIO, AWS S3, Selectel, Yandex Object Storage и другие сервисы с S3 API. Можно настроить endpoint, регион, тип адресации, bucket и server-side encryption.

Access Key и Secret Key не возвращаются обратно в браузер. Повторная проверка соединения использует сохранённые зашифрованные реквизиты.

## Переменные окружения

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `MASTER_KEY` | Главный ключ шифрования, обязателен | — |
| `DATABASE_PATH` | Путь к SQLite-базе | `/data/routervault.db` |
| `SESSION_TTL_HOURS` | Срок действия сессии | `12` |
| `COOKIE_SECURE` | Cookie только по HTTPS | `false` |
| `TZ` | Часовой пояс расписания | `UTC` |
| `BACKUP_HOUR` | Час запуска до настройки | `3` |
| `BACKUP_MINUTE` | Минута запуска | `0` |
| `BACKUP_WORKERS` | Максимум параллельных устройств | `4` |
| `ADMIN_USER` | Начальный логин до мастера | `admin` |
| `ADMIN_PASSWORD` | Начальный пароль до мастера | `change-me` |

S3 можно задать переменными из `.env.example`, однако для новой установки удобнее использовать мастер настройки.

## Постоянные данные и восстановление

В Docker Compose база хранится в volume `routervault-data`. Для аварийного восстановления необходимо сохранить:

1. файл `/data/routervault.db` или его системную копию из S3;
2. исходное значение `MASTER_KEY`;
3. доступ к S3 bucket с архивами.

Без исходного `MASTER_KEY` расшифровать сохранённые пароли невозможно. Не меняйте ключ после первоначальной настройки и храните его отдельно от резервной копии базы.

Для восстановления остановите контейнер, верните базу в `/data/routervault.db`, укажите прежний `MASTER_KEY` и снова запустите сервис.

## Безопасность

- публикуйте RouterVault только через HTTPS;
- не открывайте порт приложения и SSH MikroTik всему интернету;
- используйте отдельного пользователя RouterOS;
- ограничивайте SSH firewall-правилом по адресу сервера;
- храните `MASTER_KEY` в менеджере секретов или защищённых переменных Portainer;
- ограничьте права S3-ключа нужным bucket;
- регулярно обновляйте образ и зависимости.

Файл `.rsc` может содержать чувствительные элементы конфигурации. Относитесь к нему как к секрету, даже если RouterOS скрывает часть значений.

## Ограничения

- планировщик рассчитан на один экземпляр RouterVault;
- SQLite и локальная блокировка не предназначены для горизонтального масштабирования;
- доступность backup-команд зависит от версии RouterOS и прав пользователя;
- восстановление `.backup` выполняйте на совместимом устройстве и версии RouterOS.

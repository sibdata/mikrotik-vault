# RouterVault

Self-hosted панель для автоматических резервных копий MikroTik RouterOS в S3-совместимое хранилище.

## Возможности

- добавление MikroTik по IP/hostname и SSH;
- ежедневный запуск по расписанию и ручной запуск;
- создание зашифрованного бинарного `.backup` и читаемого `.rsc`;
- загрузка в любой S3-совместимый сервис с серверным шифрованием;
- история запусков, этапы выполнения, повтор ошибок и скачивание через временную подписанную ссылку;
- шифрование паролей роутеров мастер-ключом;
- защита от параллельного запуска одного устройства;
- проверка SSH/SFTP при добавлении устройства;
- контрольные суммы SHA-256 и индивидуальный AES-пароль для `.backup`;
- профиль администратора и восстановление пароля через SMTP;
- мастер первоначальной настройки.

## Запуск

1. Скопируйте `.env.example` в `.env` и обязательно замените `MASTER_KEY`.
2. Запустите `docker compose up -d --build`.
3. Откройте `http://адрес-сервера:8080` и пройдите мастер настройки.

Мастер проверит S3, создаст bucket при его отсутствии, настроит администратора,
почту восстановления и расписание резервного копирования.

Для production рекомендуется поставить перед приложением HTTPS reverse proxy (Caddy, Traefik или Nginx). Не публикуйте порт 8080 напрямую в интернет.

## Portainer

Для развёртывания из Git используйте `docker-compose.portainer.yml`. Стек подключается
к внешней сети Nginx Proxy Manager `angie_nmp_portainer-web-net`, хранит базу в Docker volume
и не публикует порт приложения наружу. В переменных стека обязательно задайте постоянный
`MASTER_KEY` длиной не менее 24 символов. Менять его после настройки нельзя.

## Пользователь RouterOS

Создайте отдельного пользователя только для бэкапов. Ему нужны права, достаточные для `/system backup save`, `/export` и чтения файлов по SFTP. SSH должен быть включён в `/ip service`, а firewall — разрешать подключение только с IP сервера RouterVault.

## Важное

- `MASTER_KEY` нельзя менять после первоначальной настройки: иначе сохранённые пароли невозможно расшифровать.
- При удалении устройства метаданные удаляются из локальной базы, но объекты в S3 сохраняются.
- Планировщик рассчитан на один экземпляр контейнера. Не масштабируйте сервис горизонтально без внешней очереди/блокировки.
